# 第 2 章 程序员分层与工程范式

## 学习目标

- 理解 AI 时代程序员正在发生怎样的分层
- 区分 `Vibe Coding` 和 `Agentic Engineering` 的不同层次
- 建立“写代码能力”与“组织 AI 生产能力”之间的差别意识

## 核心内容

如果把 AI 时代的程序员简单划分，可以先从四层看：理解 LLM 的人、做 LLM 应用的人、做 Agent 开发的人，以及开发 Agent 本身的人。这个划分不只是技术栈不同，而是离“生产系统的核心控制权”有多近。

理解 LLM 的人更偏底层认知，知道模型能力边界、上下文窗口、推理与生成差异。做 LLM 应用的人，更多是在现有产品里嵌入 AI 能力。再往上一层，是围绕任务流、工具调用、状态管理去做 Agent 开发。最靠上的一层，是开发 Agent 的人，也就是去构建帮助别人工作的工程 Agent、设计 Agent、流程 Agent。这一层最接近新的生产关系。

这里就会引出第二个关键判断：`Vibe Coding 是人写代码的下限，Agentic Engineering 是人写代码的上限。` 这句话不是贬低 Vibe，而是在说它解决的是最低摩擦的实现问题。你描述一个感觉，AI 给你一段代码，这会显著提升起步速度。但如果你要交付一个复杂系统，仅靠 vibe 不够，因为复杂系统不是拼速度，而是拼边界、约束、验证和可维护性。

`Agentic Engineering` 则要求人从“实现者”切换为“编排者”。你要定义任务拆分、工具权限、上下文边界、失败处理和验收标准。换句话说，Vibe 更像一种快速生成手段，而 Agentic Engineering 更像一套系统化生产方式。

## 程序员分类

### 1. LLM 理解者

重点在模型原理、能力边界和评估方式。

### 2. LLM 应用开发者

重点在产品集成、接口封装和业务接入。

### 3. Agent 开发者

重点在任务流、工具调用、状态控制和可执行过程。

### 4. 开发 Agent 的工程师

重点在构建“帮助别人工作的系统”，比如 code agent、design agent、workflow agent。

## 两种工程范式

### Vibe Coding

优点是起步快、反馈快、低门槛，适合验证想法和快速原型。

### Agentic Engineering

适合复杂系统、团队协作和高要求交付。它要求人能够定义规范、控制质量、设计流程，而不是只负责敲代码。

## 实践

结合你自己的工作，判断你当前更接近哪一层：

- 你是在理解模型？
- 在做 AI 应用接入？
- 在做 Agent 工作流？
- 还是已经在构建帮助别人工作的 Agent？

然后再回答：你现在的主要工作方式更接近 Vibe Coding，还是 Agentic Engineering？为什么？

## 小结

本章的重点是建立分层意识。AI 时代最重要的不是“会不会用某个模型”，而是你处在哪一层，以及你是否已经从写代码者转向工程系统的组织者。
