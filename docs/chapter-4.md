# 第 4 章 RD 方法论与工具栈

## 学习目标

- 理解你纲要中的 RD 视角到底指向什么
- 掌握 SDD、Skill MCP、SOP/WF 这些关键词背后的方法论位置
- 建立对 code agent、design agent 和底层模型分层关系的认识

## 核心内容

如果前面三章回答的是“为什么世界变了”，这一章回答的就是“研发怎么真正跟上”。你给出的 RD 线索很清晰：`SDD`、`Skill MCP`、`SOP/WF`。它们其实对应的是三个层次。

第一层是 `SDD`，也就是规范驱动。它的核心思想不是先写代码，而是先写清楚要做什么、边界是什么、如何验证。这一点在 Agent 时代比过去更关键，因为 AI 一旦拿到模糊目标，会快速放大模糊。SDD 的价值就在于，把模糊需求转成可执行规范。

第二层是 `Skill MCP`。可以把它理解为能力的可插拔化和工具化。过去团队经验很多停留在“某个人很会做”；现在更高效的方式是把能力封装成工具、技能、插件或服务器接口，让 Agent 可以稳定调用。这会把个人经验转成系统能力。

第三层是 `SOP/WF`，也就是标准操作流程与工作流。真正的生产力提升，不是一次生成一段漂亮代码，而是把需求澄清、方案生成、实现、验证、复盘这些动作串成稳定流程。只有流程稳定，团队才敢把更多工作交给 Agent。

## 工具分层

### 1. Code Agent

这类工具直接进入研发执行环节，比如 Claude Code、Codex、Cursor、Kiro、Copilot 等。它们解决的是“代码如何被生成、修改、验证”。

### 2. Design Agent

这类工具处理界面、交互和视觉方案，例如 Claude Design、Stitch。它们把设计工作也带入 agent 化流程。

### 3. 底层 LLM

Claude、Gemini、GPT、DeepSeek、GLM 等提供底层推理与生成能力。它们像发动机，但不等于完整系统。

## 一个实用判断

当团队开始谈 AI 落地时，不要只问“用哪个模型”，而要按顺序问三个问题：

1. 规范是否清楚，也就是有没有 SDD。
2. 能力是否封装，也就是有没有 Skill 或 MCP 接口。
3. 流程是否闭环，也就是有没有 SOP/WF。

这三个问题如果缺任何一个，AI 工程化都会停留在演示层面。

## 实践

选一个常见研发任务，比如“新增一个文档页面”或“实现一个小功能”，用下面的格式写出流程：

- 规范是什么？
- 哪些能力可以封装成 Skill 或 MCP？
- 整个 SOP/WF 分几步？
- 哪一步由人审核，哪一步由 Agent 执行？

## 小结

本章的重点是把 AI 从“会生成东西”推进到“能进入研发体系”。真正决定团队上限的，不是模型名字，而是规范、能力封装和工作流闭环。
